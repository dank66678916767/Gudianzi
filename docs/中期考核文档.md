# 孤电子队战队中期考核

**队伍名称**：孤电子队战队  
**开发环境**：Keil 5 (STM32F103)  

## 1. 底盘选型与硬件踩坑（供电与驱动）(10.11)

**功能描述**：
确定底盘的全向移动方案，并解决初期电机启动时的供电不足与驱动模块烧毁问题。

**开发历程与思考**：
*   **底盘选定**：为了让小车能实现横向平移和原地旋转，我们最终敲定了**麦克纳姆轮**方案，通过四个轮子的矢量合成来实现全向移动。
*   **动力换血**：测试时发现，电机加机械臂同时动作时电流极大，干电池根本无法支撑。我们果断更换了**18650锂电池组**（额定7.4V），既支持重复充电，又能提供充足动力。
*   **驱动踩坑与迭代**：最初我们使用的是 `DRV8833` 驱动模块。结果一上电电机不仅不转，单片机还频繁重启。排查后发现，启动瞬间的峰值电流太大，`DRV8833` 根本扛不住。后来更换为 `TB6612` 驱动模块，动力问题完美解决，小车终于“起飞”了。
*   **为什么这样做**：提前进行大电流测试，避免了在赛场上因驱动板烧毁导致直接失去比赛资格。TB6612 带载能力更强，容错率更高。

## 2. 底层代码开发与结构组装 (10.12~10.13)

**功能描述**：
在 Keil 5 环境中配置 STM32 底层外设（PWM、SPI），并完成机械臂与底盘的物理结合。

**开发历程与思考**：
*   **底层开发**：在 Keil 5 里死磕 C 语言代码。成功配置了定时器输出 PWM 波（用于控制底盘电机和机械臂舵机），并调通了 `SPI` 接口，实现了对 PS2 手柄数据的读取，基础控制框架搭建完成。
*   **结构防松设计（“血包棒”救场）**：在安装机械臂时，发现螺丝和螺母在底板上互相干涉，无法拧紧。我们突发奇想，利用“血包棒”垫在中间作为缓冲垫。没想到效果极好，既起到了防松作用，又增加了减震效果，完美解决了物理干涉问题。
*   **加固处理**：为了防止机械臂在夹取道具时发生晃动，我们利用底板上的多余孔洞重新布局，将机械臂底座进行了多点固定，死死锁在底盘上。

## 3. 软硬件联调与 Bug 排查 (10.14~10.16)

**功能描述**：
软硬件初步结合后的全系统测试，解决程序卡死、通信失败及舵机失控等突发问题。

**开发历程与思考**：
*   **Bug 1：程序死机**。烧录代码后小车完全没反应。利用 Keil 5 的 Debug 单步调试，发现程序卡在等待手柄数据的 `while` 循环里死锁了。**解决**：增加了超时退出（Timeout）机制，等不到数据就自动跳过，避免了主程序瘫痪。
*   **Bug 2：手柄连不上**。接收器指示灯亮了，但小车毫无反应。**解决**：查阅资料发现是对上电时序有严格要求。我们在初始化代码中增加了特定的延时，并加入了手柄复位指令的重发，最终成功配对。
*   **Bug 3：机械臂舵机失控**。底盘能跑，但机械臂不动。**排查**：起初误以为是代码里电机和舵机的 PWM 定时器冲突，重新分配了引脚复用（Remap）。但后来仔细检查发现，其实是另外三个舵机的信号线在组装时被扯断了，导致只有 3 号舵机有反应。**解决**：理清了定时器配置并重新排查线路。目前（中期考核阶段）虽然只有三号舵机受控，但控制逻辑已完全跑通。

## 4. 功能整合与操控优化 (10.16~10.18)

**功能描述**：
实现底盘的丝滑控制，并完成手柄按键与机械臂的映射逻辑。

**开发历程与思考**：
*   **移动手感优化**：写完麦轮解算算法后，发现推完摇杆松手后，小车还会自己乱跑。我们在代码里加入了**摇杆死区处理（Deadzone）**和线性映射。现在推摇杆非常丝滑，没有漂移感。
*   **机械臂控制**：目前虽然只有三号舵机受控，但把手柄按键与舵机联动的整套控制逻辑已经跑通，后续更换线路后即可实现全功能。
